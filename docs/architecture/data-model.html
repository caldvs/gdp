Transactions

  • New bill version: put V#nnn and LATEST, and the IMGHASH# row on first parse.
  • Create session: META + every PART# row, plus JCODE# and BILLLOCK#, both create-if-absent.
  • Amend mid-session: new bill version + LATEST + reconciled META and participant rows.
  • Lock claims: META to claiming and the creator's PART# row together.
  • Split change: SHARE# row (guarded by version) and the diner's PART# row.
  • Payment update: PAY# row and the payer's PART# row; mark-paid is conditional on pending.
  • Abandon: deletes BILLLOCK#. Close does not.

Lifetimes

  • Kept: users, auth identities, bills, image hashes, payments, table fees.
  • 30 days: sessions (META, PART#, SHARE#), join codes, bill locks.
  • Short-lived: sign-in codes 10 min, idempotency 24 h, venue cache 90 days.
  • Check: sessionStore.create writes META's ttlAt as an ISO string. DynamoDB TTL ignores non-numbers, so a session that never gets a later META write keeps its META row while its other rows expire.
