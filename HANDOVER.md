# Handover — Group Dine Pay (web)

_Last updated 31 Oct 2026._

The app lets the lead diner photograph a bill and check the scanned items. They then open a session that others join by QR code or join code. Each diner claims or splits their items and pays the lead directly by bank transfer. It is **web only now**: the Expo/iOS/Android app has been dropped.

## Where things are

- Repo: `~/Developer/gdp` on Callum's Mac. It's an npm workspaces monorepo on Node 22.
  - There's no git remote yet and nothing has been pushed.
  - `inspo/` is Callum's (UI reference images) and is untracked; don't commit it.
- `apps/api` is the backend:
  - Hono on Lambda, with DynamoDB (single table) and S3. Infrastructure is CDK (`infra/main.ts`).
  - It was imported from `gdp-backend` with its history.
  - `openapi.yaml` is the API contract.
- `apps/web` is the frontend:
  - Next.js 16 App Router, React 19 and TanStack Query.
  - Styling is the "Calm" design system CSS, copied into `app/globals.css`, plus an app layer at the bottom of that file.
- `packages/core` (`@gdp/core`) is shared TypeScript, consumed as source:
  - API client and hooks (from the old mobile app)
  - `lib/owed.ts` for money maths, plus payout, QR and image helpers
  - `src/api/schema.d.ts`, generated by `npm run gen:api`
- `test-fixtures/bills/` has 21 real bill photos for testing uploads.

## Running it

```sh
npm install
npm run dev:local
```

`dev:local` starts the API on :3000 and the web app on :8081. The API runs Docker Compose (DynamoDB Local and MinIO), so Docker Desktop must be running.

- **Sign-in:** locally you sign in with just an email. A new email gets a fresh account; a known one shows that user's bills. This is `POST /v1/auth/email/dev-sign-in`, which only exists when the API points at a local DynamoDB.
- **Environment:** `apps/api/.env.local` is gitignored and holds the Gemini key. `S3_ENDPOINT` must be `http://localhost:9000`.
- **Tests:**
  - `npm test` runs the unit tests: api 67, core 61.
  - `npm run test:int -w apps/api` runs 174 integration tests and needs DynamoDB on :8000 and S3 on :9000.
  - `npm run typecheck` checks types across the repo.
  - A husky pre-commit hook runs lint-staged and the typecheck.

## Key decisions (don't undo without asking)

- **Bank details:** the lead's bank details stay on their device and reach guests in the QR link's `#p=` fragment (ADR-0002).
  - Manual payment mode doesn't need server-side bank details.
  - The pay screen prefers the QR details.
- **Trust-based payments:** guests pay while the session is still in `claiming`; there's no lock-claims step in the UI. What a guest owes is computed on the fly, and `packages/core/lib/owed.ts` mirrors `paymentService.computeOwedForParticipant`. Keep the two in step.
- **Splits (ADR-0006), as changed today:**
  - The person who splits an item sets `ways`, meaning how many people shared it. Each sharer owes price ÷ ways.
  - The settings are stored per item as `SHARE#<itemId>` rows, with a version number and the last 10 activity entries.
  - `PUT /v1/sessions/:id/shares/:itemId` changes `ways`. Only people in the split can call it; it can't go below the number already in it, and it's frozen once any of them has paid.
  - Joining a full split adds one more way. Leaving reopens the spot.
  - The web app shows the other sharers a notice when someone joins, leaves or changes the number. The "seen" state is in localStorage.
  - `splitShare` (API) and `sharePence` (core) must agree.
- **Bill review screen:**
  - The bill photo is shown beside the items: pinned at the top on phones, side by side at 960px and wider.
  - Items can be edited in place by tapping them, and each edit is saved as soon as the editor closes.
  - Unclaimed items show a "Claim" pill; joinable splits show "Join".

## Gotchas

- **Lockfile:** npm 10 crashes ("edgesOut") when there's no lockfile, so regenerate it with `npx npm@11 install`. `npm ci` works fine once the lockfile exists.
- **MinIO image:** `minio/minio` was removed from Docker Hub, so use `cgr.dev/chainguard/minio`.
- **META row:** never write `shares` or `shareSettings` into the session META row. `sessionStore.metaOnly()` strips them.
- **Moving the repo:** it used to live on an exFAT SanDisk. If anything ever comes back from there, remove the `._*` files and restore the exec bits.
